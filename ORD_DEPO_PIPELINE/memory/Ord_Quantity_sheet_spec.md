# Лист «ORD Количество поручений» (Ord_Quantity matrix)

Машиночитаемая схема колонок: [Ord_Quantity_headers.json](Ord_Quantity_headers.json).  
Исходные требования: [TZ_Ord_Quantity_MSG_XLS.md](TZ_Ord_Quantity_MSG_XLS.md) §4.8, §7; принцип на скрине [list_Ord_Quantity_describe.png](../scrins/list_Ord_Quantity_describe.png).

---

## 1. Источник данных (source)

| Слой | Назначение |
|------|------------|
| **СВОД_операций** | Метрики **Z … VF**, **XP**, **XF**, **Q** — по прямому совпадению «Тип поручения» с группой колонок (**XP**/**XF** уже в СВОД после переклассификации **P**/**F**, см. [Svod_sheet_spec.md](Svod_sheet_spec.md)); строки **A–C** — справочник **«Счета депo»**. |
| **REPs** (ГПБ) | Колонки **T** и **Y**: из листа **REPs** только если **«Номер операции»** ≠ **ОТКАЗ**; **«Операция»** = **«ПЕРЕВОД ЦЕННЫХ БУМАГ ПО РАЗДЕЛАМ СЧЕТА ДЕПО»** (после `lower()`, **ё→е**, сжатие пробелов); **«Тип сделки или иного основания»**: **«прием цб на учет»** → **T**, **«внесение изменений»** → **Y**; фильтр по **«Дата операции»** (месяц/год как у СВОД). Заполнение REPs — `fill_reps_from_rep_xls.py`. |
| **Dks / REP** | Блок «Хранение комплектов» и часть placeholder-колонок — **не подключены**; ячейки **0** (см. §6). |

---

## 2. Ключ строки листа (row key)

**Базовый набор строк** — все счета из листа **«Счета депо»**, колонка **«Номер счета депо»** (`seed_matrix_from_depo_directory`): заполняются колонки **A–C** (депозитарий, владелец, счёт).

**Метрики Z…VF, Q, T/Y** — из **«СВОД_операций»** и **REPs** за выбранный месяц; привязка к строке — по номеру счёта через справочник **«Счета депо»** (депозитарий/владелец/номер из справочника, если счёт найден).

Строки СВОД с пустым или прочерком «-» в счёте **не участвуют** в агрегации метрик.

---

## 3. Фильтр периода (period)

Учитываются только строки СВОД, у которых «Дата операции» попадает в заданный **месяц и год** (формат **ДД.ММ.ГГГГ**). Параметры CLI: `--year`, `--month`.

---

## 4. Маппинг «тип поручения» → группа колонок (bucket)

| Группа на листе | Типы из колонки «Тип поручения» СВОД | Примечание |
|-----------------|--------------------------------------|------------|
| **Z … VF**, **XP**, **XF**, **Q** | Те же буквы | Прямое совпадение **N** СВОД с группой на листе (**XP**/**XF** формируются при сборке СВОД из **P**/**F**). |
| **T**, **Y** | — | **Не из СВОД.** Заполнение из листа **REPs** (ГПБ): сначала **«Операция»** = **«ПЕРЕВОД ЦЕННЫХ БУМАГ ПО РАЗДЕЛАМ СЧЕТА ДЕПО»**; затем **«Тип сделки или иного основания»** = **«прием цб на учет»** → **T**; **«внесение изменений»** → **Y** (сравнение после `lower()` и нормализации **ё→е**). |
| **Q** | `Q` | **ГПБ:** каталог **`GPB/SPR`**, файлы **`Q*_<счёт>_*.pdf`** — **Закл** = число PDF по счёту, **Лист** = сумма **(страниц − 1)** по каждому PDF (см. §5). Не из СВОД. |
| **S(u)** | — | **ГПБ:** **`GPB/SPR`**, архивы **`SPR_<счёт>_*.zip`** / **`.7z`** — **Закл** и **Лист** = число архивов по счёту. **Регион:** **`REGION/SPR`**, только файлы в корне; рекурсивно **zip/7z** → **PDF** с **`[счёт]`** в имени — **Закл** и **Лист** = число PDF по счёту (см. §5). |
| **DF**, **DP** | `DF`, `DP` | Блок **«Хранение комплектов»**: число **строк** **СВОД_операций** с **N** = **DF** / **DP** по паре **депозитарий + счёт** (строка матрицы A–C); **«в пред»** — **0**; **«в тек»** — **`=в пред+DF−DP`**. |
| **E** | — | В матрице нет колонки; строки СВОД не агрегируются. |

Типы без правила маппинга в матрицу **не попадают**.

---

## 5. Метрики **Пор.** и **Закл** (и **Лист**)

Согласовано с идеей ТЗ: при отсутствии основания поручение (order) считается по уникальному ключу **счёт + раздел + тип + дата** — в СВОД это отражено колонкой **«ОдноТипОперТипРазд»** (аналог бывшей колонки **Q** книги).

| Метрика | Определение в агрегаторе |
|---------|---------------------------|
| **Пор.** | Число **различных** ключей поручений внутри ячейки. Для **T, Y, RF, RP, VF, VP, F, P, XP, XF** из **ГПБ / REGION / ВТБ СД** — **одно «Пор.» на уникальное имя файла** (**«Источник»** СВОД или REPs для **T/Y**); для **РСД** — уникальные значения колонки **«Основание»** СВОД (пустое основание — один общий ключ); для прочих депозитариев — **«ОдноТипОперТипРазd»**. |
| **Закл** | Сумма по строкам СВОД значений «Количество закладных»; если не число — берётся **1** (одна закладная (mortgage) на строку). |
| **Q — Закл** | Число файлов **`Q*.pdf`** в **`GPB/SPR`**, у которых сегмент имени после первого **`_`** совпадает с **Счет Депо** строки. |
| **Q — Лист** | По каждому PDF: **(число страниц − 1)**; по счёту — **сумма** по всем таким файлам (несколько PDF — суммируются). |
| **DF / DP** («Хранение комплектов») | Число **строк** СВОД с **N** = **DF** или **DP** (без дедупликации по **«ОдноТипОперТипРазд»**). |
| **S(u) — Закл / Лист (ГПБ)** | Число архивов **`SPR*_<счёт>_*.zip`** / **`.7z`** в **`GPB/SPR`** (сегмент после первого **`_`** = **Счет Депо**); в обе подколонки — одно и то же число. |
| **S(u) — Закл / Лист (Регион)** | Число **PDF** с префиксом **`[счёт]`** в имени внутри архивов **`S_*` / прочих `.zip`/`.7z`** в корне **`REGION/SPR`** (вложенные папки не сканируются; вложенные архивы — да); в обе подколонки — одно и то же число. |

Для группы **Q** колонки **Пор.** на листе нет (`skip_por` в JSON).

## 6. Блоки-заглушки (placeholder)

Группа **«Хранение комплектов»**: **DF** и **DP** — **число строк** **СВОД_операций** с соответствующим **N** по **депозитарий + счёт**; **«в пред»** — **0**; **«в тек»** — **`=в пред+DF−DP`**.

**Обслуживание счета** (между **Назначение УЛ** и **Первичное описание**): **1**, если **Депозитарий** = **АО «ДК РЕГИОН»** и **Счет Депо** начинается с **VL** (без учёта регистра); иначе ячейка **пустая**.

**Первичное описание** / **Закл** (перед **Признак** и **Прочие расходы**): ячейки **пустые** — для ручного ввода; шапка с заливкой `#F8CBAD`.

**Признак** / **ENC**: lookup по **Счет Депо** (колонка **C**) в
`{REPORTS_DEPO_DIRECTORY}/depo_validation/Справочник.xlsx`, лист «Таблица сопоставления 1»,
col **L** «ENC (Код ЦБ)»; нормализация счёта `strip().casefold()`; значения с «кодификатор» / «см.»
в справочнике → пустая ячейка. CLI: `--sprav-workbook`.

Остальные placeholder-группы (**S(b)**, **Spr(u)**, **Spr(b)**, **Открытие счета**, **Назначение УЛ**, **Прочие расходы**) — **0**, структура сохранена для ручного ввода.

## 7. Скрипт и модуль

- Логика: [`src/ord_quantity_excel.py`](../src/ord_quantity_excel.py) (чтение СВОД, агрегация (aggregation), разметка заголовков).
- CLI: [`scripts/fill_ord_quantity_from_svod.py`](../scripts/fill_ord_quantity_from_svod.py).

**Риск импорта (import):** модуль **не** импортирует `svod_excel` (избегание циклов (circular imports)); индексы колонок СВОД дублируются по именам заголовков. **Уверенность:** High.

---

## 8. Инициализация книги (template)

Команда создания книги с листом-шаблоном (заголовки (headers), без данных СВОД):

`python scripts/init_ord_quantity_workbook.py --out 2026_01/2026_01_Ord_Quantity.xlsx`

Дальше: заполнить СВОД (и справочники), затем:

`python scripts/fill_ord_quantity_from_svod.py --workbook 2026_01/2026_01_Ord_Quantity.xlsx --year 2026 --month 1`
